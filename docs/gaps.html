Roadmap: gaps that no existing project fills

Eleven things the research looked for and did not find. Five of them are what this project intends to build first. Almost all of it is planned and not built; the one exception so far is the evaluation lab.

On this page

  1. Status
  2. Planned first
  3. Larger builds, later
  4. Other open gaps

Status

Almost nothing on this page has been built. The exception is an evaluation lab in the repository's lab/ directory: a first, narrow piece of gap 5 (a harness that measures one small model on personal-assistant tasks, on one Mac) and a prototype of the "enforcement outside the model" idea in gap 2 (a confirmation gate for sending and deleting, tested only against stand-in tools). Nothing else below should be read as a description of working code.

Each gap is stated as something the research looked for and did not find. An absence of search results is not proof that nothing exists.

The plan is to take Hermes Agent as the base rather than write a new agent, build items 1, 2, 4, 5 and 8 first, and publish the measurements on this site. Items 3 and 7 are the larger builds.

Planned first

1. A scoped permission broker for personal data

Planned, not built

Small single-purpose helpers that hold one narrow OS grant each (Messages read, Messages send-with-approval, Mail drafts, Calendar) and expose a minimal, logged API to any agent. Today the agent's host process holds Full Disk Access and Automation rights, and scoping is done by prompts and allowlists. Apple's 27.3 changes make this urgent [9][10].

2. A cross-agent review queue

Planned, not built

A standard "draft, approve, send" outbox for messages, mail and PRs, with enforcement outside the model, usable from Hermes, OpenClaw or a coding agent. Only fragments exist (Apple2Agent's mail approval, exec approval prompts).

4. One assistant across macOS and Linux with the Mac as data hub

Planned, not built

A documented, tested topology: gateway and Apple data on a mini, Linux and Mac thin clients, voice satellites, with authentication. The pieces exist in Hermes v0.23; the reference deployment does not.

5. An honest, reproducible model-selection harness for personal-agent tasks on Apple Silicon

Planned, not built

Per RAM tier, per runtime, per quantization, measuring tool-call correctness, refusal to fake results, time to first token with and without cache, and memory. SiliconBench covers serving engines on an M5 Pro and one pair of M4 Pros [12]; the public indexes are mostly estimates [30].

8. A local-first supervisor for unattended jobs

Planned, not built

Run directories, transcripts, budgets, digests, dead-man alerts and a uniform health view across launchd and systemd jobs and across harnesses. Each agent has its own partial version.

Larger builds, later

3. Linux parity for personal data

Planned later, not built

A permissioned bridge for calendar, contacts, notes and messages on Linux, including on Hyprland-based desktops, and an agent adapter for blueferry.

7. A native macOS front end that bridges App Intents and Shortcuts to a local agent

Planned later, not built

macOS 27 allows a third-party model behind Apple's session API and lets Siri reach app content through schemas [20][21]. An open project that exposes a self-hosted agent's actions as App Intents, and system intents as agent tools, would give OS-enforced consent for free.

Other open gaps

These were found by the same research. They are not on the first-pass plan.

6. Measured voice latency on M4-class Macs

Open gap, not scheduled

I found component numbers and an RTX 4090 end-to-end figure, but no published end-to-end measurement for a cascaded or full-duplex assistant on an M4 mini.

9. Guardrail templates for git work

Open gap, not scheduled

Ready-made token scopes, hooks, rulesets and wrapper scripts for "read-only triage" and "PR-only changes", tested against several agents.

10. Linux inference on M3 and M4

Open gap, not scheduled

Blocked on a Vulkan driver. omarchy-mlx has a tester kit that asks for M4 hardware.

11. Small task-specific adapters as a supported workflow

Open gap, not scheduled

Collect traces, label with a hosted model, train a LoRA with MLX on a mini, evaluate, deploy to the pinned small model. OpenJarvis points in this direction [19]; there is no packaged path for a home setup.
